# 深蹲视频指导：实验接口与人工验证

膝内移接入以[算法交付版](膝内移算法终版.md)为准。本页记录通用视频指导接口与早期实验背景。

## 当前状态

现有 Python 命令行接口可由 Java 后端在接收并保存用户视频后调用，输出 JSON；本项目未实现 HTTP 上传服务或用户页面。视频处理为离线方式。依赖见 `requirements-squat-skeleton.txt`，模型为 `models/pose_landmarker_lite.task`。

膝内移只在调用方指定正面视角时分析，候选依据膝中心的水平位移。接口输出候选、待复核和无法判断三种状态。加上 `--heel-review` 可输出脚跟抬起的实验候选，按脚跟相对同侧前脚掌的上移给出侧别和时间。脚部遮挡或站姿参照不足时返回 `unknown`。前脚掌、躯干协调和平衡的观察项返回 `unknown`。

加上 `--all-labels --knee-mode high-recall` 可输出 Part1 的 12 项人工标签对应的机器观察。脚内缘和外缘离地、腰背弓曲、腰椎过伸的字段说明所缺证据。明显失衡的候选只覆盖动作中的抬脚横移。候选只用于复核，`reason_code` 区分未触发与证据不足。

最低点停留按实际可见的屈曲角稳定时段判断。视频在停留时结束，且可见稳定时段达到 1.5 秒时，也可给出候选。此时 `cycle_index` 可能为 `null`，播放器仍可按 `start_sec` 和 `end_sec` 定位。侧偏记录髋中心相对双脚的水平位移和侧别。

## 分析视频

```powershell
python scripts/squat_offline_api.py --video 'C:\path\input.mp4' --model models/pose_landmarker_lite.task --run eval/squat_skeleton_offline_v1_20261030 --action normal_squat --camera-view front --output 'C:\path\analysis.json'
```

`--action` 支持 `normal_squat`、`wide_squat`、`narrow_squat`；`--camera-view` 支持 `front`、`side`、`oblique`、`front_or_oblique`、`unknown`。输出路径必须不存在，避免覆盖。`--reference-registry` 可选；参照比较仍是未验证的动作轨迹差异，不是正确性评分。

JSON 保留旧版字段，并增加 `guidance`：

- `cycles`：每次动作开始、最低点、结束、时长与估计膝屈曲角。
- `observations`：每个问题的状态、时间段、解释性证据和验证状态。膝内移的 `candidate` 和 `review_required` 均用于人工复查。
- `subjective_feedback.questions`：追问与允许的选项；`guidance` 根据用户回答给出停止或专业评估提示。
- `followup_comparison`：动作、视角匹配时仅描述两次周期时长等变化，不宣称改善。

候选 JSON 示例见 `eval/squat_guidance_review_20261031/真实视频分析示例.json`。示例使用自录视频，勿对外分享原始视频或可能包含身份信息的路径。

## 录入主观反馈并比较下一次练习

JSON 中三项均可省略。选项分别为 `pain`: `none`、`mild`、`sharp_or_worsening`、`unknown`；`instability`、`swelling_locking`: `no`、`yes`、`unknown`。这些是用户报告，系统不会从画面推断疼痛。

将回答保存为 UTF-8 JSON，例如 `{"pain":"none","instability":"no","swelling_locking":"no"}`，然后运行：

```powershell
python scripts/squat_guidance_followup.py --result 'C:\path\analysis.json' --answers-json 'C:\path\answers.json' --previous-result 'C:\path\previous.json' --output 'C:\path\analysis_with_feedback.json'
```

首次练习不传 `--previous-result`。若上一轮的动作或视角未指定或不一致，结果为无法比较。也可以在初次分析时用 `--answers-json` 和 `--previous-result` 传入。

## 人工标注与验证

`eval/squat_guidance_review_20261031/视频待标注清单.csv` 包含 621 条 Part1 视频和 36 条示范视频，仅为清单；空白字段不是标签。已标记训练排除的视频保留并显示 `training_screen`，训练或实验筛选应排除它们。根据实际问题创建一条或多条标注记录，填写 `issue_type`、`can_judge`（`yes`/`no`）、`present`（`yes`/`no`）、发生时间、复核人及备注；不确定时 `can_judge=no`，不要填写成否定。需要教练共同确认表现的标注口径；示范视频阶段时间不自动成为动作质量标签。

在开发样本定规则，用未参与开发的人物组成独立测试集，并保留每个视频的身份、动作、视角。采集正面和侧面、遮挡和不同站距，以及足部与地面清楚可见的样本；在授权条件下补录。先查阅原数据集许可，保护自录人员隐私。

`evaluate_squat_issue_labels.py` 接收人工视频级标签 CSV 和 `video_id,issue_type,status` 预测 CSV，输出分动作、视角的候选精确率、含弃判漏检的敏感度、未知比例及不可判断却产生候选的数量。候选未触发时为弃判，不能算作已判断的阴性；结果不足以评估片段时间精度或证明人物隔离。

示范阶段比较位于 `eval/squat_guidance_review_20261031/已复核示范阶段比较.json`，复核时候选对标注者可见，不能当作独立盲测。应补充独立人物、隐藏候选的标注与片段时间误差验证，满足阈值由团队与教练共同制定后再考虑正式启用。
