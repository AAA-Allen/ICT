# M12 持续运行基线

状态：Windows / Python 3.13 的 200 次顺序本机 HTTP 基线已验证；远端矩阵待执行。本工具是确定性资源检查，不评价真实模型效果，不代表生产吞吐、并发或进程内存上限。

## 固定负载与判据

规范在 `examples/resource_baseline.py` 的 SPEC 中预先定义，版本为 m12-baseline-v1，执行前保存 spec.json，报告同时复制该规范。没有根据实测耗时或内存调整门槛。

默认执行 200 次 HTTP POST，每次工作流使用脚本流式模型发布 128 个固定片段，然后执行一次受管只读工具，持久保存运行、生命周期、调用审计与 checkpoint。模型和工具各应实际执行 200 次；没有外部模型调用，不虚构 token usage。

| 检查面 | 预先固定的通过条件 |
| --- | --- |
| 执行 | 所有工作流 COMPLETED，实际模型/工具调用数各等于 rounds |
| 缓存 | 最多 8 个运行、每运行 32 条事件、单事件 128 字节、每运行 1,024 字节、全局 8,192 字节；每次 POST 后无活动流遗留 |
| 过期 | 结束运行保留 1 秒；在有限轮询期内，访问 stats 后缓存运行数及 payload 字节归零 |
| SSE | 最新运行的晚订阅明确报告截断，推送保留的 32 个片段；携带末游标重连不重复 token |
| 线程 | 观测峰值不超过初始值加 8；服务关闭并有界等待后回到初始线程数以内 |
| 文件数量 | 状态目录文件数 ≤ 5 × rounds + 4 |
| 文件大小 | 状态目录字节 ≤ 100,000 × rounds + 65,536 |
| 计时与进程内存 | 只观测，不设通过门槛，不换算 SLA |

这是特定短期顺序负载的合理性预算，**不是任意业务、任意输出长度的通用资源额度**。缓存使用较小容量以主动触发历史淘汰和运行回收；单进程 HTTP 服务及 Runtime 为真实实现，模型为明确脚本替身。

## 使用与证据

```bash
python -m examples.resource_baseline --rounds 200
```

输出目录为 outputs/resource-baseline/baseline-批次 ID，含 spec.json、report.json 及 state 下的实际运行文件。每 25 次采样，并记录启动、过期后和关闭后的状态；每次请求均检查缓存边界。报告包含源码 commit/dirty、平台、Python、实际调用、固定判据结果、缓存峰值、线程、文件和内存样本，以及 POST 耗时 p50/p95/max。

`--rounds` 支持 1..10000，少于 200 标记 SMOKE；不能把短 smoke 当作完成 200 次基线。通过退出 0，失败退出 1。CI 接入 16 次 smoke 和证据留存，仍需实际远端结果才能声称跨平台验证。

工具应在独立进程运行；内部临时绑定流总线，并在结束时恢复。不要在已有生产者工作的宿主进程中并发调用 run_baseline。原始服务器日志可自行重定向到文件。

## 测量口径

- 缓存 payload_bytes 统计 UTF-8 节点名及文本，不等于整个进程的内存。
- tracemalloc 在负载期间开启，记录 Python 分配的当前值和峰值，会给请求带来额外开销。
- resident_bytes 为 Windows 当前工作集或 Linux 当前 RSS；平台不支持时为 null，不以峰值代替当前值。
- 线程样本为 Python threading 线程数，不包括全部 OS 原生线程；既记录负载峰值，也检查服务关闭后的回落。
- 请求计时包含 HTTP、图执行和持久化，不含定期目录扫描和 SSE 探针；总耗时另列。
- 文件大小为逻辑文件字节，不是磁盘分配空间。状态目录包含运行、checkpoint、审计、生命周期与索引；不统计报告本身。
- 过期检查会访问 stats 触发惰性清理，不能据此宣称存在后台 TTL 清理线程。

## 已有测量与结论

2026-11-08 首轮 200 次本机负载：全部完成，模型与工具各调用 200 次；缓存峰值 8 个运行、256 条事件、4,864 字节，过期后归零；线程从初始 1 到峰值 3，关闭后回到 1。状态目录 802 个文件、3,142,857 字节。该轮带 tracemalloc 的 POST p50 约 68.5 ms、p95 约 81.6 ms、最大约 204.5 ms，总耗时约 16.4 秒。这是该机器的一次观测值，不是性能承诺。

流缓存清理后，Python 分配与工作集并没有回到初始值。Runtime 生命周期、服务端索引、内存分配器等仍可能保留数据；运行文件也按运行数累积，没有磁盘归档或删除策略。本基线不证明进程整体内存恒定或无限运行安全。

结论：本机该规模下，缓存、线程回收和文件合理性预算满足既定判据；已有数据支持继续 M13 的受控参考任务。更长持续时间、并发、多会话、真实模型延迟与故障注入仍需另定负载，不能用本次数据替代。先观察实际应用增长，再决定 Runtime 元数据保留、文件归档或存储迁移。
