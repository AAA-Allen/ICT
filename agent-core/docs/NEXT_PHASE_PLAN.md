M8/M9 已完成；M10 离线 28 次验收通过，真实模型配置缺失；M11 独立安装与交付准备已实现，本机完整回归为 452 项 Python 测试及 6 项前端测试，正常 wheel 有 34 项安装检查。真实模型、远端 CI、许可证和版本决策仍未完成。

本轮按本机工作台优先排序。若主要使用方式变为 SDK 或多人服务，应重排界面与认证任务；流式正确性、资源边界和真实任务证据仍需保留。

## M12：流式正确性与持续运行边界

### 任务

| 编号 | 具体工作 | 涉及位置 | 验收标准 |
| --- | --- | --- | --- |
| M12-01 | 固化流式游标、缺口及重连协议；先补可失败的回归 | streaming、HTTP SSE、前端订阅、相关测试 | 用小缓存复现历史淘汰后漏读；覆盖断线、晚订阅、连续模型节点、审批后再连接；测试能区分重复、丢失和明确缺口 |
| M12-02 | 用稳定进度替换 deque 下标；接通续读、去重与缺口提示 | TokenBus、SSE、EventSource 消费者 | 在缓存窗口内重连不重复且不漏读；超过窗口时明确报告缺口并查询权威状态，不能静默拼接为完整输出；服务重启后不伪称能重放内存 token |
| M12-03 | 设计并接通已结束运行的缓存回收与容量限制 | TokenBus 与运行生命周期接点 | 单事件、单运行及全局容量有明确边界；关闭保留期可配置；不误清活动运行或同一运行的后续模型节点；回收后查询语义可解释 |
| M12-04 | 统一模型响应大小边界 | models.complete、complete_with_tools、complete_stream | 非流式工具回复、SSE 单帧及累计输出超限时停止并返回明确原因；只用本机 HTTP 替身验证，不发起后续不允许的工具副作用 |
| M12-05 | 记录持续运行基线及协议迁移说明 | 定向测试、验证报告、兼容文档 | 用确定性负载观察缓存数量/字节、线程、文件增长和耗时；测量与阈值先定义；保留数据而不将其称为生产吞吐保证 |

### 实施顺序

先执行 M12-01/M12-02，形成第一份可独立 review 的修复；再做 M12-03/M12-04，最后记录 M12-05。针对现有协议先写兼容设计，不直接把历史缓存立即删除，也不只提高容量来掩盖游标问题。

初始回归至少包含：淘汰一条后继续读取、超过容量后持续发布、断线重复连接、已过期游标、多模型节点、等待审批再恢复、运行结束回收。总容量不足时需定义活动运行的行为，不能把被清理历史当成空的新运行。

### 完成定义

- 流式探针由失败变为符合新协议；Python 与前端相关测试能覆盖跨层行为。
- 现有运行、审批和恢复语义保持；共享路径改动后执行必要完整回归。
- 给出资源上限、保留策略、重连和服务重启边界；更新兼容说明及调用方迁移方式。
- 按实际平台分别记录验证。没有外部模型也能完成离线契约验收。

## M13：工作台与工具型参考 Agent 闭环

### 参考任务

读取明确允许目录中的资料，形成审阅结论和待办草稿，经用户批准后保存到指定输出目录。只读工具与写入工具分开授权，写入须审批；路径校验由工具执行，不依赖模型自行遵守提示词。

参考应用、提示词、工具和样例数据放在 examples。复用现有 agent_loop、Harness、审批和恢复，不把领域状态写入内核。不在本阶段增加任意 shell、任意目录读写或独立 Planner 服务。

### 任务

| 编号 | 具体工作 | 验收标准 |
| --- | --- | --- |
| M13-01 | 装配一个受控工具型参考 Agent，并提供离线和真实模型入口 | 由模型选择被暴露的只读工具；写入前暂停；拒绝零写入；批准后恢复遵守已确认结果复用；越权路径在工具执行前拒绝 |
| M13-02 | 工作台展示模型/工具尝试、重试、预算和真实 usage | 优先消费已有 harness-events；从服务端事实派生展示，不新造执行日志；缺失或损坏的证据显示未知，不能显示成零或成功 |
| M13-03 | 解释审批动作及恢复阻断原因 | 动作说明来自工具声明的展示白名单；不输出私有参数全文；UI 与服务端恢复预检一致，未知结果不能被“重试”按钮自动重发 |
| M13-04 | 接通本机审批 token 的界面使用 | 凭证仅在本次页面内存使用，不进入 localStorage、URL、运行记录或日志；缺失/错误凭证可识别；不扩大为完整多用户认证承诺 |
| M13-05 | 增加浏览器级任务 smoke 与必要的离线资源处理 | 真实服务下覆盖提交、流式、审批、拒绝、恢复及刷新查询；外部字体/图标不可用时核心流程仍可操作；脚本替身和真实模型结果分别标记 |

### 完成定义

从独立安装的运行包或明确说明的参考应用入口，用户可以完成一次任务及一次受控阻断，查询相关调用事实，并在重启后解释状态。离线端到端与真实模型验收分别记录；没有凭证时保持真实项未验收。

只在已有 API 无法表达必要一致性时增加只读聚合接口，避免为每个页面建立另一套状态机。完成闭环后再评估是否有必要提供独立应用安装器。

## M14：小规模试用与交付复验（候选）

1. 复用 wheel 检查，在干净环境验证新增资源、配置、CLI 和参考任务入口。
2. 用固定公开资料和少量实际使用记录，收集任务成功/阻断原因、人工干预次数、真实调用、usage 缺失比例与资源数据。不在观察结果后改写通过标准。
3. 复查文档可否由另一位使用者独立完成安装与排障，再作候选版本决定。
4. 按失败分布选择后续投入：检索不足再考虑 RAG，文件成本有数据再考虑存储迁移，明确并发需求再考虑调度。未有需求时保留当前单机模型。

M14 不以扩大模型、工具或 Agent 数量作为完成指标。
