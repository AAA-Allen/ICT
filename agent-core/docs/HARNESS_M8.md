# Harness M8：恢复契约收口

状态：实现与专项验收完成，最终全量验证结果见文末。M8-01 已复现并修复模型循环跨访问复用旧审批结果的问题。

## 已复现的问题

实际循环图 `work → gate → work → gate → end` 在中间重建 Runtime 后：普通 `tool` 节点第二次访问进入新审批；`agent_loop` 第二次访问复用第一次的工具结果，直接完成。失败用例见 `tests/test_recovery_contract.py`。

## 调用身份与兼容设计

- 运行由 `run_id` 标识，节点由 `node_id` 标识，同一节点访问的边界由 `state_version` 标识。节点成功提交后状态版本必定前移；重放未提交的节点保持相同版本。
- `execution_id` 标识每次执行尝试，重启重放时会变化，不用它作为批准可复用的依据。`request_id` 标识这次访问中的某个具体审批请求；同一模型循环可有多个顺序审批。
- 两类节点统一通过私有快照存储按访问读取：相同版本允许恢复；较早的已完成快照属于旧访问，不用于新访问；未来版本或未完成的旧访问返回 `APPROVAL_REQUEST_MISMATCH`。
- 无 `state_version` 的历史快照仍可读取和查询，但节点自动恢复返回 `APPROVAL_VISIT_UNKNOWN`。维护者核对后应通过应用迁移补充可信的版本或创建新运行，不推测调用身份。
- 模型循环保存新快照时记录当前节点状态版本。输出键或路由变化、已批准工具不再暴露时停止恢复。
- 原始低层 `DefaultModelToolLoop.resume_pending` 没有节点上下文，继续由显式调用方保证快照所属访问；高层节点统一执行访问校验。

## 故障验证目标

| 故障点 | 重启后的预期 |
| --- | --- |
| 审计或预算占用未落盘 | 不执行对应外部调用 |
| 预算已占用但调用结果未可靠落盘 | 停止自动调用，返回模型或工具结果不明 |
| 审批工具已领取 STARTED，结果未落盘 | 不重复执行，需人工核对 |
| 审批工具结果已落盘，节点未提交 | 复用结果，保留原工具额度消耗 |
| 调用结果或工具结果已落盘，预算结算失败 | 保守阻断后续新调用；不得静默删除未结算占用 |
| 子运行已启动但结果未落盘 | 不重新委派，返回 `SUBAGENT_OUTCOME_UNKNOWN` |
| 节点 checkpoint 提交失败 | 使用最后可信边界恢复；无可信 checkpoint 则不可恢复 |

非审批普通工具与模型的完整结果并未自动持久化为可重放的调用结果。已结算调用在 checkpoint 重放时可能再次发起，并再次占用预算；非审批副作用工具仍须由应用提供跨恢复幂等契约。此边界必须在验收矩阵中明确，不能承诺外部副作用恰好一次。

## HTTP 与工作台行为

`resumable` 表示检查当前持久事实后允许发起恢复尝试，不保证恢复必定成功；装配配置、能力或外部依赖变化仍可让节点明确失败。

查询与 `/resume` 共用预检：缺少可信 checkpoint、访问身份未知或冲突、审批被拒绝、工具仍为 `STARTED`、预算存在未结算占用时，不将其报告为可直接恢复。`POST /resume` 对这些情况返回 HTTP 409 和对应原因码，预检不会改写运行生命周期。

等待运行只有在决定为 `APPROVED` 且工具与参数摘要一致时才报告可恢复。普通未决定的等待继续返回 `NOT_RESUMABLE`。

工作台对仍为 `WAITING_APPROVAL` 但工具实际为 `STARTED` 的运行显示人工核对入口；不能仅按运行 `BLOCKED` 状态判断是否需要核对。人工核对后重新查询恢复资格。审批结果核对只更新该工具快照，不会自动删除或结算其他未结算运行额度；该类额度故障仍需应用审核处理。

## 可执行验收矩阵

以下用例使用临时目录，恢复时重新创建 Runtime、审计和存储实例。模型与工具均为明确的确定性替身，验证的是恢复契约，不是模型质量。

| 场景 | 实测结果 | 后续动作 |
| --- | --- | --- |
| 普通工具和模型循环两次进入同一节点，中间重启 | 两次不同审批；工具恰执行两次；工具和模型额度按实际尝试累加 | 第二次访问重新批准 |
| 历史快照缺少访问版本 | 记录可读取，恢复阻断 `APPROVAL_VISIT_UNKNOWN` | 可信迁移或新建运行 |
| 模型循环输出键、路由或工具暴露变化 | 在执行前阻断错配或未暴露工具 | 修正配置后显式恢复 |
| 预算占用写入失败：模型、只读工具 | 外部调用为零；修复存储后显式恢复成功 | 可重试 |
| 占用写入成功后模拟进程中断：模型、只读工具 | 新 Runtime 阻断结果不明，未发起外部调用 | 人工核对占用事实 |
| 外部调用后结果审计失败：模型、只读工具 | 外部仅调用一次；重启后不重发 | 人工处理结果不明 |
| 结果审计完成、额度结算失败：模型、只读工具 | 外部仅调用一次；未结算占用阻止新调用 | 审核未结算占用 |
| 审批工具 STARTED 写入失败 | 无副作用；后续显式恢复执行一次 | 修复存储后重试 |
| 审批工具结果快照写入失败 | 副作用一次，快照保留 STARTED；重启不重复执行 | 人工核对工具结果 |
| 审批工具结果已落盘、checkpoint 失败 | 重启复用结果；工具与其预算占用均不重复 | 显式恢复 |
| 审批工具结果已落盘、额度结算失败 | 重放不再执行该工具；后续工具被未结算占用阻止 | 审核未结算占用 |
| 模型/只读工具已结算、最终 checkpoint 失败 | 从旧边界再次调用；新增一次预算占用 | 受额度约束的显式恢复 |
| 子运行结果未落盘 | 重启返回 `SUBAGENT_OUTCOME_UNKNOWN`，不重复委派 | 人工核对 |
| 子运行结果已落盘、父 checkpoint 失败 | 父重放复用子结果，无第二次模型调用 | 显式恢复 |
| HTTP 存在 STARTED、历史快照、未结算模型额度或缺少 checkpoint | 查询 `resumable=false`，恢复返回 409，无副作用 | 核对或修复持久事实 |
| HTTP 人工确认 STARTED 工具已完成（无其他未结算额度） | 重新报告可恢复，并复用工具结果 | 显式恢复 |

测试位置：`tests/test_recovery_contract.py`、`tests/test_server.py`。M7 的已完成结果边界重放、批准参数错配及未知结果不重复执行用例继续保留；既有拒绝审批保护也继续回归。

## 兼容与交付限制

- 新增原因码 `APPROVAL_VISIT_UNKNOWN`；已开始但结果未知的 HTTP 恢复由原来的“启动恢复后返回 BLOCKED”调整为“预检返回 409”，不再为被拒绝的恢复制造生命周期事件。
- 新模型循环快照写入 M7 已支持的可选 `state_version` 字段，不改存储 schema 主版本。历史字段缺失不再允许高层节点自动猜测所属访问。
- 自定义审批存储提供方须实现 `for_node_visit(run_id, node_id, state_version)`；缺少该接口时模型循环明确失败，不静默重新调用模型。
- 没有新增通用的运行额度核对/结算 API，也不替应用判断外部系统事实。完整模型回复重放、非审批工具跨恢复幂等和跨进程事务仍不在本阶段内。
