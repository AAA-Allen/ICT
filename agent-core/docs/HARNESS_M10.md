# Harness M10：应用场景验收

状态：固定输入、两个应用示例、离线 HTTP 验收和报告入口已实现；真实模型验收尚未完成，当前环境未配置模型。固定输入与判据见 `examples/acceptance_cases.json`（版本 `m10-v1`），先定义判据，再执行模型。

## 场景与验收标准

资料审阅只读取本地固定资料，判断是否明确包含回滚步骤。模型产物须为 verdict、summary 和 evidence；引文必须逐字存在于所读资料。缺少资料、空资料或缺少必要证据时明确阻断，不允许补造引用。

任务分流将固定任务归入 ops、support 或 needs_information。分类引用必须来自任务文本，负责人由工具查询，不由模型编造。写入本地分配记录必须等待批准；拒绝不写入，重启恢复不重复调用前序模型或重复分配。

输入均为公开合成数据，不包含真实账号、私有文档或生产工单。领域规则仅放在 examples，内核保持通用。

## 检查面的区别

- 框架契约：权限、额度、调用次数、审计、审批与重启恢复是否遵守预期。
- 任务产物：终态、原因码和固定业务字段是否满足预先定义的预期；结构合法并不代表分类正确。
- 模型表现：离线脚本回复不作为真实模型效果证据；真实模式按固定输入报告结果，并通过重复运行观察终态和核心业务字段的一致性，不评价措辞一致性。

没有配置真实模型时必须生成 NOT_RUN 报告，真实模型验收保持未完成，不把离线通过换算成真实模型通过。

## 使用

从仓库根目录执行：

```powershell
python -m examples.workflow_acceptance --mode offline --repeat 2
python -m examples.workflow_acceptance --mode real --repeat 2
```

离线模式启动只监听 loopback 的临时 HTTP 模型替身，使用真实 `OpenAICompatibleModel.complete` 适配器及 `ctx.calls`，不访问外部模型。14 个固定用例重复两次，共 28 次执行。脚本回复只取 `scripted_reply`，不读取 expected 断言；应用随后独立校验结构与引文，验收器再检查业务预期。

真实模式从服务端环境读取 `AGENT_MODEL_BASE_URL`、`AGENT_MODEL_API_KEY`、`AGENT_MODEL_NAME`。配置齐全时运行 12 个适用于真实模型的固定用例；脚本特有的坏回复和 HTTP 503 注入不发送给真实服务。输入只含合成资料与合成任务；传给模型的用例标识为不含语义的摘要，不泄露 ready、ops 等预期标签，也不包含 expected 或脚本答案。

本阶段使用非流式协议，适配器只发送模型名和消息；温度等生成参数采用服务端默认值，报告不虚构其值。模型名是配置的名称，不保证服务端别名所指模型版本。真实配置不完整或无效时，不启动替身兜底，也不运行任务，生成 NOT_RUN 报告。

批准、拒绝与批准后重启由验收脚本按固定动作执行，只写该批次目录的本地分配 JSONL，不操作真实工单系统。重启用例重建 Agent、Runtime 和存储对象，用持久 checkpoint 恢复；不在报告中声称实际杀死了服务进程。

CLI 退出码：0 为该次验收通过，1 为用例失败，2 为真实模型未执行。默认输出位置为 `outputs/acceptance/<mode>-<batch-id>/`，每次使用新目录，不覆盖旧证据。

## 用例范围

| 场景 | 固定情况 |
| --- | --- |
| 资料审阅 | 有回滚步骤、缺少回滚证据、空资料、资料不存在、读取权限不足、读取超时、伪造引文 |
| 任务分流 | ops 批准、support 批准后重启、拒绝批准、分配权限不足、工具额度耗尽、模型 HTTP 不可达、任务不明确 |

报告分别记录框架检查、业务产物检查和固定路径调用次数。真实模式不将模型的错误分流认定为框架失败：结构合法但类别错误时，框架检查可以通过，业务产物必须失败。总体通过要求框架与任务都通过；离线模式还必须满足预先指定的调用次数。两种模式都核对预期副作用次数，并逐条校验分配记录的任务、队列和负责人与运行结果一致，不能只凭返回的 assigned 字段判断成功。

自动产物检查关注终态、类别、负责人和引文来源；摘要只做结构与长度校验，其叙述真实性和可读性仍需人工按模板复查。报告记录实际模型调用和完成回复数量；若运行全部在模型调用前阻断，即使用例预期通过，也不能标记为真实模型验收通过。

## 证据与报告

每批次保存 `report.json`、便于阅读的 `report.md`、输入原件 `fixtures.json`，每个用例保存运行结果、Harness 审计、checkpoint 和必要的审批私有快照。报告包含输入版本及 SHA-256、源码 commit 与工作区修改状态、模型配置名称、运行配置、状态与原因码、适配器调用数、实际工具调用数、额度占用数和副作用次数。

重复运行的一致性只比较终态、原因码及预先指定的核心业务字段，不比较自然语言措辞；一致性也不代表质量正确。usage 只累计适配器实际返回且内核支持的计数字段，同时记录覆盖的调用数；缺失 usage 时为 NOT_REPORTED、totals=null，不用零或费用估算代替未知信息。

报告 schema_version 为 2。用例执行或报告提取异常时保持 FAIL，不改为 NOT_RUN；错误行保留已观察到的调用次数与仍存在的证据路径。审计丢失或不可读时，usage.status 为 EVIDENCE_UNAVAILABLE，完成回复数及额度占用数为 null；无法解析分配记录时副作用次数也为 null，不能将证据缺失写成零调用或零副作用。

报告不记录 API key、Authorization 头或可能含凭证的服务 URL，也不收集原始异常消息。真实模型报告的人工复查清单见 [报告模板](M10_MODEL_REPORT_TEMPLATE.md)。自动化测试中的 real 模式使用本机 HTTP 替身，只验证接线，不能算真实模型验收。
