- **Harness M8 恢复契约**：普通工具与模型循环共用审批访问校验，模型循环快照记录状态版本；循环图的新访问重新批准，历史访问身份缺失返回 `APPROVAL_VISIT_UNKNOWN`。故障矩阵覆盖占用、结果、结算、checkpoint 和子运行结果丢失。
- **恢复预检**：查询与 HTTP `/resume` 统一检查可信边界、审批和未结算调用；结果不明时报告不可直接恢复并返回 409，工作台保留人工核对入口。

- **Harness M7 普通工具节点**：声明式 `tool` 与模型工具循环共用调用流水线、运行级预算及审计；支持可选有限重试、人工审批和重启后显式恢复。审批快照记录可选 `state_version`，同一边界重放复用已落盘结果，图循环再次访问需重新审批。

- 本机服务支持可选审批 Bearer token，保护批准决定、结果核对与恢复的写入入口；通过 `--approval-token-env` 从环境变量读取。

- **Harness M5 模型重试底座**:模型流水线可选有限次数的瞬态错误重试，逐次消耗预算并记录 attempt 与退避；默认关闭，工具不自动重试。
- **Harness M5 llm 配置**:`llm` 节点可显式配置模型重试次数和退避基数；流式回复产生 token 后不再重试该请求。
- **Harness M5 agent_loop 配置**:`agent_loop` 可显式配置模型重试，重试消耗 `max_rounds`；审批私有快照保存实际模型调用次数，重启续跑不会恢复已花费的额度。
- **Harness M5 工具重试与幂等契约**:`agent_loop` 可配置工具瞬态错误重试；只读工具可重试，副作用工具仅在应用提供稳定键调用和结果查询后可重试。每次尝试消耗预算并写入审计，需审批工具不自动重试。
- **Harness 预算审计**:模型与工具调用结果、重试 attempt 和预算拒绝事件记录节点内已用及剩余调用额度。
- **Harness M6 运行级预算**:可选跨 `llm` 与 `agent_loop` 节点的持久调用额度；checkpoint 恢复不重置已用额度，未结算的模型或工具调用阻止自动重发。
- **Harness M6 同步委派预算**:`subagent` 在同步调用期间继承父运行的模型与工具额度，checkpoint 续跑仍计入父额度；预算审计标记子运行来源。
- **Harness M6 持久委派恢复**:父审计预先记录稳定子运行 ID；父节点重放时复用已持久化子结果，结果缺失或请求错配时阻止自动重复委派。
- **Harness 第一阶段**:独立的模型/工具调用预算对象、可替换的模型/工具循环接口和统一工具调用入口；`agent_loop` 新增 `max_tool_calls`（默认 16），超限返回 `MAX_TOOL_CALLS`；新增 PRD、设计说明和开源项目调研。
- **Harness M1 调用事实**:新增 `HarnessEvent`、`HarnessAudit` 及内存/文件存储；模型和工具流水线记录请求、结果、失败和预算拒绝，支持按 `run_id` 查询并在审计写入失败时返回 `AUDIT_WRITE_FAILED`。
- **Harness M2 工具策略**:工具支持风险元数据；`agent_loop` 只能调用当前节点暴露的工具，未暴露、需批准和策略异常分别返回稳定原因码。
- **Harness M3 上下文装配**:新增确定性的消息数/字符数裁剪器，`agent_loop` 支持 `max_context_messages` 与 `max_context_chars`。
- **Harness M3 增量**:`llm` 节点接入相同上下文限制和模型调用审计；按完整用户轮次裁剪，保留工具调用/结果关联，只记录适配器提供的真实 token usage。
- **Harness M3 诊断**:模型请求审计记录上下文裁剪数量，必需消息超限时写入明确的拒绝事件。
- **Harness M4 等待契约**:新增独立 `WAITING_APPROVAL` 状态、待批准请求摘要、checkpoint 与审计记录；普通恢复不能跳过批准。批准决定与执行恢复尚未实现。
- **Harness M4 决定事实**:新增本地持久化批准决定记录，校验请求 ID 和参数摘要；重复决定幂等，冲突决定明确报错。服务端决定入口和执行恢复仍待实现。
- **Harness M4 决定接口**:本机 HTTP 可查询和提交批准决定；拒绝转为 `BLOCKED/APPROVAL_REJECTED` 且不可普通恢复，批准仅记录决定并保持等待。
- **Harness M4 私有快照**:默认模型工具循环在等待前持久化恢复所需的内部调用事实，重启读取时核对参数摘要；公开接口仍只返回请求摘要。
- **Harness M4 一次性执行声明**:私有快照支持持久化 `PENDING`、`STARTED`、`COMPLETED`；匹配批准决定后才能领取执行，重启后未记录结果的调用返回 `TOOL_OUTCOME_UNKNOWN`，避免静默重放。批准后恢复流程仍待接入。
- **Harness M4 批准工具入口**:注册表和 Harness 工具流水线可基于持久化批准决定执行单次工具调用，执行前核对参数摘要并领取声明，执行后持久化结果；策略、能力和审计继续生效。运行恢复与模型循环续跑仍待接入。
- **Harness M4 循环续跑**:默认模型工具循环可从私有快照恢复已批准的工具调用和后续消息，复用已持久化结果并重建预算；服务端显式恢复尚待接入。
- **Harness M4 批准后显式恢复**:新增 `Runtime.resume_approved()`,核对持久化 `APPROVED` 决定与等待请求一致后从检查点续跑;生命周期新增 `WAITING_APPROVAL → RUNNING` 的 `run.resumed(APPROVED)` 迁移。`agent_loop` 节点检测到本节点活动快照时自动走续跑,不重新询问模型。HTTP `/resume` 接受已批准的等待运行(不接受 `state_updates`),无决定时保持 `409 NOT_RESUMABLE`;已批准等待运行报告 `resumable: true`。重启端到端验收通过:副作用工具跨重启恰好执行一次。
- **Harness M4 人工核对路径**:`POST /api/runs/{run_id}/approval-resolution` 记录操作者对 `STARTED` 不明结果的核实结论(`COMPLETED` 附输出或 `FAILED` 附原因码),快照标记 `resolved_by: OPERATOR` 并写入 `tool.outcome_resolved` 审计;之后的恢复复用核对结果,不重放工具。
- **Harness M4 多次审批**:决定存储与私有快照升级为每运行多条(文件 schema v2,兼容读取 v1),按请求 ID 绑定/追加;`load_for_request` 与 `active_for_node` 支持同一运行顺序经历多次等待-批准-恢复。
- **工作台审批入口**:等待中的运行渲染批准面板(工具名、请求 ID、参数摘要),支持批准并继续与拒绝;`TOOL_OUTCOME_UNKNOWN` 渲染人工核对表单;待审批状态独立呈现。新增 `examples/approval_agent.json` 与 `examples/approval_server.py` 审批演示。
- **基础层收口**:发布包包含 `agent_lite` 和工作台静态文件；服务端会话记忆落盘并在重启后恢复；运行索引保存会话归属，索引写入失败时回滚内存状态并报告错误。
- **工作台会话聊天视图**:带会话历史的完成运行渲染为聊天气泡(用户/助手分侧),取代纯时间线。
- **llm 多轮对话**:`llm` 节点 `history_key` 参数——对话历史从会话记忆读入并写回,同会话运行自动携带上下文;无会话 BLOCKED `SESSION_MEMORY_REQUIRED`,历史损坏 FAILED `HISTORY_INVALID`。
- **工作台工具轮次可视化**:时间线自动渲染 `*_rounds` 状态键中的工具调用轮(工具名、参数、结果摘要)。

## [0.3.0] - 2026-10-25

模型接入、领域工具桥接与工程硬化:从确定性编排平台到可接真实智能的运行时。

### 新增

- **单实例约束**:存储目录级 OS 文件锁(flock/msvcrt,进程死亡自动释放),拒绝同目录第二服务实例;真实子进程硬杀 e2e 测试验证锁自动释放与记录完好。
- **流式输出**:适配器可选 `complete_stream(messages, on_delta)` 约定(内置适配器已实现,标准库 SSE 解析);`llm` 节点优先流式、无则回退 `complete`;进程内 `TokenBus`(历史回放 + 容量上限)桥接节点与 SSE;`/events/stream` 新增 `token` 帧,工作台实时渲染。
- **模型接入**:`agent_core.models.OpenAICompatibleModel`——纯标准库实现的 OpenAI 兼容 chat completions 适配器(单请求、不重试、失败带稳定原因码且不泄露密钥/载荷);`AGENT_MODEL_*` 环境变量配置(半配置视为未配置);声明式 `llm` 节点(模板提示 + fail-closed:未配置 BLOCKED、传输失败 FAILED 带原因码);服务端模型注入与 `/api/health` 的 `model_configured` 报告;`examples/assistant_agent.json`;本地假端点契约测试(不触网)。
- **工具能力声明**:声明式 `tool` 节点新增 `capabilities` 参数,显式授予工具所需能力(未声明 → BLOCKED `CAPABILITY_DENIED`,绝不隐式授予);工具抛出携带 `reason_code` 属性的异常时原样透传为节点失败原因码。
- **请求来源防护**:POST/DELETE 校验 Origin(localhost CSRF)与 Host(DNS rebinding),跨站请求 403;非浏览器客户端不受影响。
- **结构化运行冲突**:`RunConflictError(reason_code)` 取代消息文本约定(`RUN_ALREADY_ACTIVE`/`RUN_ID_ALREADY_USED`/`CHECKPOINT_INCOMPATIBLE`),服务端表驱动映射。

### 变更(0.x 破坏性)

- `ModelAdapter.complete` 移除未实现的 `tools`/`context` 参数,签名收敛为 `complete(messages)`;接口不再声明未交付的能力。
- `RunResult.stopped_at` 更名为 `stopped_at_node`(语义即节点名);旧名保留为只读弃用别名,持久化写新键、读兼容旧记录的 `"stopped_at"` 键,HTTP 负载键同步更名。

## [0.2.0] - 2026-10-25

在 0.1.x 图运行时之上新增完整的 Agent 平台层。核心运行时语义不变,全部新增能力保持确定性、fail-closed 与可审计边界。

### 新增

- **Agent 框架外壳**:`AgentBuilder`/`Agent`/`AgentSpec`,模型、工具、记忆通过协议注入;`AgentNodeContext.cancel_requested` 为活回调,支持节点内协作取消;`AgentResult` 保留完整运行时结果;`Agent.describe()` 暴露图拓扑。
- **声明式 Agent 装配**:`agent_core.nodes` 确定性节点工厂(`validate_input`/`split_steps`/`template`/`tool`/`route_by_value`/`subagent`),JSON 配置装配,装配期校验;`register_node_factory()` 扩展;`--config` 启动装载与 mtime 热重载(先校验后原子替换,失败保留旧版)。
- **子 Agent 编排**:`subagent` 节点把工作委派给其他注册 Agent 作为嵌套运行(独立 run_id/Trace/生命周期),终态原样传播;配置间依赖环装载期拒绝;委派共享会话记忆。
- **HTTP 服务**(`agent_core/server.py`,纯标准库):同步与异步(`wait=false`)运行、运行查询、生命周期事件、协作式取消、检查点检查与显式恢复(`state_updates` 状态修正)、SSE 实时事件流、会话记忆(创建/查看/清除)、运行列表分页/过滤与元数据缓存;运行→Agent 归属索引持久化,跨进程恢复。
- **工作台前端**:实时生命周期时间线、节点级 Trace 检查器(Trace/生命周期表格、状态 JSON)、运行中取消、可恢复运行的状态编辑对话框、嵌套运行钻取、服务端运行日志分页、Agent 拓扑展示、会话记忆清除;服务不可达时自动降级为离线演示模式。
- **会话记忆**:每会话 `InMemoryMemory`,`MemoryStore` 协议落地,同会话运行共享上下文。
- **打包**:`pip install -e .` / wheel,`agent-core-server` 控制台入口,版本单一来源化。
- **CI**:GitHub Actions 矩阵(Windows/Ubuntu × Python 3.10/3.13),unittest + pytest 双跑。
